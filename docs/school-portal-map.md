真正的空白只有三块值得看：**班车服务**、**校历**、**图书馆研讨间预约**。

## 三、⚠️ 一个重要更正：座位预约 = 图书馆座位

**此前我一直以为 `seatlib` 是「第三方自习座位系统」，与图书馆无关。错了。**

证据（2026-09-27 实测，只读免认证接口）：

```
POST https://seatlib.bit.edu.cn/api/Seat/tree   {"date":"2026-09-27"}
→ {"data":[{"id":"1","name":"徐特立馆","children":[
      {"id":"2","name":"三层","children":[
        {"id":"3","name":"视听学习空间"},
        {"id":"4","name":"自然科学图书第一阅览室"},
        {"id":"5","name":"自然科学图书第二阅览室"}, …]}]}]}
```

`seatlib` = **seat library**，就是**图书馆座位预约系统**（徐特立馆）。旁证：图书馆官网
（`lib.bit.edu.cn`）的《座位预约》说明与我们的契约**逐条一致**——「当日预约需开始后
**60 分钟内**刷卡签到」「次日预约需**次日 9:00 前**刷卡」「违约累计 **5 次**暂停预约 **7 日**」。

**这意味着**：

1. i北理 的「图书馆空间预约」和我们是**同一个后端**，只是它是网页/内嵌入口。
2. 我们不但没缺，反而**更强**：它只能「选座 → 预约」，我们有**抢座 / 监控 / 优先队列**，
   还有**签到时限提醒**（错过会记违约，这是官方没有任何提示的地方）。
3. ⚠️ **别再单独立项「图书馆座位预约」** —— 那是重复劳动。

## 六、修正：AI 问答为什么「不做」，以及正确的切法

> 本节是对第五节那条判断的**更正**（2026-09-27，用户质疑「AI 问答为什么不行」后重想）。

### 6.1 我原来的理由不成立

原来的理由是「成本高 + 与核心价值无关」。两条都经不起推敲：

- **「成本高」**：平台已提供**免密钥大模型调用**（`/.cloud/llm/chat/completions`），
  要写的是**上下文组装 + 工具调用 + UI**，不是训模型。成本不成立。
- **「与核心价值无关」**：**恰恰相反**。我们的核心资产就是**别人拿不到的本地私有数据**
  （课表 / DDL / 考试 / 成绩 / 校园网流量 / 一卡通余额 / 座位预约 / 空教室），
  而 AI 最擅长的事正是**把「数据」变成「回答」**。这不是无关，这是**放大器**。

### 6.2 关键区分：「问学校事务」vs「问我的数据」

「AI 问答」是个笼统的词，必须切开：

| 类型 | 例子 | 判断 |
|---|---|---|
| **问学校事务** | 「怎么办学生证」「医药费怎么报销」「选课规则」 | ❌ **不做** —— 学校有官方资料库，i北理 的 A+Campus / 智能客服已覆盖；我们做是**重复造轮子**，而且我们的知识库永远比学校旧 |
| **问我的数据** | 「我明天几节课几点」「我还有多少流量」「该去哪自习」「这学期绩点多少」 | ✅ **该做** —— 这些数据**只在本机**，网页与钉钉**答不了**。这才是我们独有的场景 |

⇒ 原来把两者一起否掉，是**判断下错了地方**。

### 6.3 两条硬约束（不满足就不做）

**约束 A：AI 只做「理解问题 → 选工具 → 组织措辞」，绝不负责计算与检索。**

LLM 会一本正经地算错 —— 而「明天 08:00 高数」这种错会**直接误事**。
所以数字必须来自**确定性代码**：

```
「我明天第一节课在哪」
  → AI：{tool: "first_class", when: "明天"}      ← 只做意图识别
  → 代码：查课表 → 08:00 高等数学 @ 文萃楼I404   ← 数字由代码算
  → AI：把结果说成人话（不许改任何数字）
```

⇒ 本质是**给已有的确定性能力加一层自然语言入口**，不是让 AI 去"知道"事情。

**约束 B：隐私开关默认关，且明确告知发送范围。**

成绩 / 一卡通余额 / 课表都会离开设备，而用户此前**明确要求「出分通知不含分数」**
（隐私边界，`ScoreLogic.summaryText` 单测锁死）——说明他对成绩敏感。

- 默认**关闭**，用户主动开
- 首次开启时明确告知「会把哪些数据发给模型服务」
- **不发送**学号、姓名、教师名、UID（脱敏）

### 6.4 时机：应该排在「结构化数据能力」之后

AI 问答是**上层**功能，它依赖下层已经能把事情算清楚：

| 想回答的问题 | 依赖的下层能力 | 现状 |
|---|---|---|
| 我明天几节课 / 在哪 | 课表查询 | ✅ 有 |
| 我还有多少流量 | 校园网取数 | ✅ 有 |
| 下一班班车几点 | **班车时刻表** | ❌ 还没做（第十九节 A1） |
| 该去哪自习 | **空教室 + 座位 + 时间的聚合逻辑** | ⚠️ 数据有，聚合逻辑没做（B1） |
| 这学期绩点 | **GPA 计算** | ❌ 还没做（C2） |

⇒ **先把下层做扎实**，AI 层是水到渠成的一层薄壳；反过来先做 AI，会得到一个
"什么都能问、答案经常错"的壳子。

### 6.5 修正后的结论

| 项 | 判断 |
|---|---|
| 「问学校事务」的 AI 问答 | ❌ 不做 |
| 「问我的数据」的 AI 问答 | ✅ **可做**，排在第十九节的第 6~7 位（下层能力就位之后） |
| 前提 | 约束 A（AI 不算数）+ 约束 B（隐私开关默认关、脱敏） |
