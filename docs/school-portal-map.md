## 三、⚠️ 一个重要更正：座位预约 = 图书馆座位

**此前我一直以为 `seatlib` 是「第三方自习座位系统」，与图书馆无关。错了。**

证据（2026-09-27 实测，只读免认证接口）：

```
POST https://seatlib.bit.edu.cn/api/Seat/tree   {"date":"2026-09-27"}
→ {"data":[{"id":"1","name":"徐特立馆","children":[
      {"id":"2","name":"三层","children":[
        {"id":"3","name":"视听学习空间"},
        {"id":"4","name":"自然科学图书第一阅览室"},
        {"id":"5","name":"自然科学图书第二阅览室"}, …]}]}]}
```

`seatlib` = **seat library**，就是**图书馆座位预约系统**（徐特立馆）。旁证：图书馆官网
（`lib.bit.edu.cn`）的《座位预约》说明与我们的契约**逐条一致**——「当日预约需开始后
**60 分钟内**刷卡签到」「次日预约需**次日 9:00 前**刷卡」「违约累计 **5 次**暂停预约 **7 日**」。

**这意味着**：

1. i北理 的「图书馆空间预约」和我们是**同一个后端**，只是它是网页/内嵌入口。
2. 我们不但没缺，反而**更强**：它只能「选座 → 预约」，我们有**抢座 / 监控 / 优先队列**，
   还有**签到时限提醒**（错过会记违约，这是官方没有任何提示的地方）。
3. ⚠️ **别再单独立项「图书馆座位预约」** —— 那是重复劳动。

## 六、修正：AI 问答为什么「不做」，以及正确的切法

> 本节是对第五节那条判断的**更正**（2026-09-27，用户质疑「AI 问答为什么不行」后重想）。

### 6.1 我原来的理由不成立

原来的理由是「成本高 + 与核心价值无关」。两条都经不起推敲：

- **「成本高」**：平台已提供**免密钥大模型调用**（`/.cloud/llm/chat/completions`），
  要写的是**上下文组装 + 工具调用 + UI**，不是训模型。成本不成立。
- **「与核心价值无关」**：**恰恰相反**。我们的核心资产就是**别人拿不到的本地私有数据**
  （课表 / DDL / 考试 / 成绩 / 校园网流量 / 一卡通余额 / 座位预约 / 空教室），
  而 AI 最擅长的事正是**把「数据」变成「回答」**。这不是无关，这是**放大器**。

### 6.2 关键区分：「问学校事务」vs「问我的数据」

「AI 问答」是个笼统的词，必须切开：

| 类型 | 例子 | 判断 |
|---|---|---|
| **问学校事务** | 「怎么办学生证」「医药费怎么报销」「选课规则」 | ❌ **不做** —— 学校有官方资料库，i北理 的 A+Campus / 智能客服已覆盖；我们做是**重复造轮子**，而且我们的知识库永远比学校旧 |
| **问我的数据** | 「我明天几节课几点」「我还有多少流量」「该去哪自习」「这学期绩点多少」 | ✅ **该做** —— 这些数据**只在本机**，网页与钉钉**答不了**。这才是我们独有的场景 |

⇒ 原来把两者一起否掉，是**判断下错了地方**。

### 6.3 两条硬约束（不满足就不做）

**约束 A：AI 只做「理解问题 → 选工具 → 组织措辞」，绝不负责计算与检索。**

LLM 会一本正经地算错 —— 而「明天 08:00 高数」这种错会**直接误事**。
所以数字必须来自**确定性代码**：

```
「我明天第一节课在哪」
  → AI：{tool: "first_class", when: "明天"}      ← 只做意图识别
  → 代码：查课表 → 08:00 高等数学 @ 文萃楼I404   ← 数字由代码算
  → AI：把结果说成人话（不许改任何数字）
```

⇒ 本质是**给已有的确定性能力加一层自然语言入口**，不是让 AI 去"知道"事情。

**约束 B：隐私开关默认关，且明确告知发送范围。**

成绩 / 一卡通余额 / 课表都会离开设备，而用户此前**明确要求「出分通知不含分数」**
（隐私边界，`ScoreLogic.summaryText` 单测锁死）——说明他对成绩敏感。

- 默认**关闭**，用户主动开
- 首次开启时明确告知「会把哪些数据发给模型服务」
- **不发送**学号、姓名、教师名、UID（脱敏）

### 6.4 时机：应该排在「结构化数据能力」之后

AI 问答是**上层**功能，它依赖下层已经能把事情算清楚：

| 想回答的问题 | 依赖的下层能力 | 现状 |
|---|---|---|
| 我明天几节课 / 在哪 | 课表查询 | ✅ 有 |
| 我还有多少流量 | 校园网取数 | ✅ 有 |
| 下一班班车几点 | **班车时刻表** | ❌ 还没做（第十九节 A1） |
| 该去哪自习 | **空教室 + 座位 + 时间的聚合逻辑** | ⚠️ 数据有，聚合逻辑没做（B1） |
| 这学期绩点 | **GPA 计算** | ❌ 还没做（C2） |

⇒ **先把下层做扎实**，AI 层是水到渠成的一层薄壳；反过来先做 AI，会得到一个
"什么都能问、答案经常错"的壳子。

### 6.5 修正后的结论

| 项 | 判断 |
|---|---|
| 「问学校事务」的 AI 问答 | ❌ 不做 |
| 「问我的数据」的 AI 问答 | ✅ **可做**，排在第十九节的第 6~7 位（下层能力就位之后） |
| 前提 | 约束 A（AI 不算数）+ 约束 B（隐私开关默认关、脱敏） |

## 七、i北理 里的 AI 助手到底是什么（2026-09-27 逆向）

> 用户提供的入口：`https://ibit.yanhekt.cn/?origin=…&inq=…`（延河课堂域名）。
> 方法是**读它的前端 bundle**（`umi.*.js`，UmiJS/React 单页应用）里的配置与接口常量 ——
> 只读、不下单、不消耗它的额度。

### 7.1 三层结构

| 层 | 地址 | 说明 |
|---|---|---|
| 前端 | `ibit.yanhekt.cn` | 延河课堂（`yanhekt.cn`，公司域名，非 `*.bit.edu.cn`）承载的 i北理 AI 页面 |
| 后端 | `aia.info.bit.edu.cn` | ⚠️ **学校信息化办公室域名的 AI 中台**（bundle 里的 `API_HOST`） |
| 另一个入口 | `aijc.bit.edu.cn/dash/chatbi/dialogIntegration` | bundle 里的 `CHAT_BIT_URL`，学校的 AI 平台 |

### 7.2 模型与调用方式（配置原文）

```js
LLM_MODEL_NAME: "chatglm3-6b",       // ← 模型
KNOWLEDGE_BASE_NAME: "cuc",          // ← 知识库
LLM_TEMPERATURE: 0.1, LLM_TOP_P: 0.2 // ← 极保守采样

PROMPT_NAME: "default", TOP_K: 3, SCORE_THRESHOLD: 0.5,
LANGCHAIN_TEMPERATURE: 0.7,
MAX_MESSAGE_LENTH: 10, MAX_HISTORY_LENTH: 1,   // ← 几乎没有多轮记忆
STREAM_RESP: true, HANDLE_KB_WITH_LLM: false,
```

请求是按**编排（流程）**发出去的，不是裸对话：

```js
params: [
  { type: "question", cmd: … },
  { type: "knowledge", cmd: { query: …, plugins: ["uuid-zhishiku"],
                              llm: { temperature, top_p, penalty_score } } },
  { type: "model", cmd: { messages: … } },
]
```

⇒ 典型 **RAG**：**先检索知识库（top3、相似度阈值 0.5），再交给模型按检索结果作答**。
配合 `temperature 0.1 / top_p 0.2`，这套配置的意图很清楚：**"照本宣科地引用规章"**，
而不是"聪明地推理"。

### 7.3 平台自带的其它能力（接口清单）

`/v1/chat/assistant`（助手）· `/v1/chat/stream/private/kb`（**私有知识库**）·
`/v1/chat/stream/super/agent` · `/v1/chat/stream/summary`（摘要）·
`/v1/chat/text_to_image`（文生图）· `/v1/chat/translation`（翻译）·
`/v1/chat/mixture` · `/v1/chat/search` · `/v1/chat/file/upload` ·
`/v1/dialogue/history/list` · `/v1/assistant/ability/list` · `/v1/ding/calendar`

⇒ 看起来是一个**通用的 AI 中台**（助手管理 + 私有知识库 + 文生图 + 翻译 + 钉钉日历），
不是只为北理写的。

### 7.4 ⚠️ 疑似「平台先给别的学校做的」

bundle 里的**页面路由名**是 `p__ai4cuc__index` / `p__ai4cuc__origin`（**ai4cuc**），
且知识库名也是 **`cuc`** —— 两者一致，指向**中国传媒大学（CUC）**。

最可能的解释：**这套 AI 平台是延河课堂的商业产品，先（或同时）服务 CUC，
北理复用时前端代码沿用了这些命名**。
（⚠️ 这是**代码命名证据 + 推测**，不是官方说法。）

### 7.5 能力评价（客观）

| 维度 | 判断 |
|---|---|
| **模型量级** | `chatglm3-6b` = 智谱 **2023 年**开源的 **6B 小模型**，量化后单张消费级显卡即可跑 —— 与 2026 年的主流旗舰（数百 B 级）**不是一个量级** |
| **适合** | 校园规章问答、办事流程指引（**恰好是 RAG + 低温采样最能发挥的场景**：答案要准、不要发挥） |
| **不适合** | 复杂推理、长文写作、代码、需要时效知识的提问 |
| **多轮** | `MAX_HISTORY_LENTH: 1` —— **几乎没有对话记忆**，每轮基本独立 |
| **时效** | 开源模型无联网；只能靠知识库补，**知识库之外的问题会答得很差或拒答** |

### 7.6 ⇒ 对我们的决策意味着什么

1. **不撞车**：它答不了「我明天几节课」「我还有多少流量」——**它拿不到我们的本地数据**。
   我们的「问我的数据」与它是**两个不同的问题域**。
2. **绝大多数场景根本不需要大模型**：查课表 / 算绩点 / 查流量，**确定性代码更准**。
   所谓"AI 问答"在我们这边，本质是**给已有能力加一层自然语言入口**（见第六节约束 A）。
3. **如果哪天真要用模型**（比如"帮我把这周的安排说成一段话"），也**不该用 6B**：
   直接接主流的强模型成本并不高，效果差距却是代差级的。

### 7.7 「居然还能生图」—— 是的，界面上就有正式入口

从 AI 页面的**懒加载 chunk**（`p__ai4cuc__index.861c7205.async.js`，554 KB；
命名规则 `{name}.{hash}.async.js`，hash 从主 bundle 的运行时映射表里取）解出中文文案，
**生图是一个独立的工作模式**：

```js
isTxt2Image: fn == 6     // fn = work_mode；fn == 1 才是普通对话
```

界面上有完整的生图 UI 文案：

| 文案 | 作用 |
|---|---|
| 「请描述您想要生成的图像内容~」 | **正向**提示词输入 |
| 「请输入希望图片不包含的元素」 | ⚠️ **负向**提示词（negative prompt） |
| 「适用文章配图」 | 场景预设标签 |
| 「长按图片保存」 | 结果操作 |

后端：`POST /v1/chat/text_to_image`，body `{prompt, dialogue_id, …}`，
带 `x-assistant-id` 头（说明要选定一个"助手/能力"）。

⇒ 支持**正/负提示词 + 场景预设**，是一套**正经的文生图功能**，不是玩具。
⚠️ 但注意：`LLM_MODEL_NAME: "chatglm3-6b"` 是**对话**模型的配置；
**生图用的是哪个模型，前端代码里看不出来**（在后端 `/v1/chat/text_to_image` 那一侧）。

### 7.8 试用的边界（我没替用户登录）

真机上打开 `https://ibit.yanhekt.cn/` → **跳到学校「数智北理」统一身份认证登录页**
（浏览器里没有登录态：钉钉内嵌 WebView 的会话不与系统浏览器共享）。

**没有代点登录**，两个理由：
1. 那是**以用户身份做学校认证**，超出"试用一个 AI"的范围；
2. ⚠️ 更实际的原因：本项目实测过 **CAS 短时间多次登录会触发风控**（要求二次验证、
   冷却约 8 小时）—— 拿用户账号去撞风控，代价太大。

⚠️ 顺带发现（值得提醒用户）：该登录页在浏览器里**自动填充了学号，密码框也是填好的状态**。
若不想让浏览器保存学校密码，应去检查自动填充设置。

### 7.9 接口层实测：能直连，但有边界（2026-09-27）

用户问「能不能不在浏览器里调用」。答案是**能** —— 它就是个普通 REST 服务，
真实地址在 **`https://aia.info.bit.edu.cn/api/user/v1/...`**
（bundle 里 `API_HOST: window.location.origin + "/api/user"`，
且 `rt.replace("API_HOST", …)` 做前缀替换；生产实际走 `LOCAL_API_HOST` 那个域名）。

⚠️ **踩过的坑**：我第一次探测 `https://aia.info.bit.edu.cn/v1/config` 拿不到东西
（GET 落到 SPA 兜底 HTML、POST 被 nginx 回 405）—— **少了 `/api/user` 这一段前缀**。

#### 鉴权分层（不带任何凭据的实测结果）

| 端点（`/api/user` 之后） | 不带凭据 | 含义 |
|---|---|---|
| `/v1/config` | 200 `{"code":11002,"配置数据无效"}` | 弱鉴权，可达 |
| `/v1/chat/text_to_image` | 200 **`{"code":1000,"禁用暂时不提供服务"}`** | ⚠️ **管理员禁用了生图**（0.37s 返回，**没触发推理**） |
| `/v1/chat/stream/private/kb` | 200 `{"code":1001,"invalid request params"}` | 参数校验层就拦下，**未到模型** |
| `/v1/dialogue/history/list` | **401 `{"code":401,"用户未登录"}`** | 需登录 |
| `/v1/chat/translation` | **401 用户未登录** | 需登录 |
| `/v1/assistant/ability/list` | **401 用户未登录** | 需登录 |
| `/v1/chat/stream` · `/v1/chat/summary` | 404 | 路径与前端常量对不上，未确认 |

认证机制（代码）：`credentials:"include"`（带 cookie）+ 可选 `badge` 头，
配套有 `POST /v1/auth/badge/cookie {badge}` 的「badge 换 cookie」端点 ——
**说明 badge/cookie 是登录后才有的东西**。

#### ⚠️ 我为什么停在这里

继续往下就是**穷举参数去绕过校内服务的参数校验** —— 那性质就从「看看它是什么」
变成「未授权访问」了；而**学校把生图功能显式禁用**（`禁用暂时不提供服务`），
说明管理方是**有意限制**的。这条线我不越。

**已做的只是**：匿名、零凭据地探了几个端点，全部在业务层被拒、**没有触发任何一次模型推理**
（响应时间 0.3~0.4 秒即是证据）。

#### 想真正命令行用起来，只有一条正路

先有凭据，再有直连：

1. **在电脑 Chrome 登录一次**（用户自己操作）→ 之后所有调用都用那个 cookie，全程 curl、不再开浏览器；
   或
2. 用户从已登录的会话里取出 `badge` 交给脚本，再用 `/v1/auth/badge/cookie` 换 cookie。

⚠️ 两条都需要用户**主动**完成登录那一步 —— 因为学校 CAS **短时间多次登录会触发风控**，
代登录的代价由用户承担（见 7.8）。
