## 十四、底图到底是谁的：OSM 官方瓦片 + 一个合规缺口（2026-09-27 查清）

### 结论：不是商业底图，是 OpenStreetMap

`map.bit101.flwfdd.xyz` 只是一层**反代**，真正的渲染源是 **OSM 基金会**：

| 证据 | 说明 |
|---|---|
| 响应头 `x-tilerender: azure-02.openstreetmap.org` | OSMF 的渲染农场主机名 |
| `Via: 1.1 varnish` + `X-Served-By: cache-nrt-*-NRT` | Fastly CDN（OSM 官方用的，NRT=东京节点）|
| `cache-control: max-age=604800` | 瓦片缓存 7 天 |
| 样式 | OSM Carto：米色底、灰框建筑、橙色主干道、浅蓝水系；「太平湖车辆段」那种灰白斜线网格是 OSM 特有画法 |

⇒ **没有「数据截止到某年」这回事**：OSM 是社区众包、持续更新，有人编辑就会跟着渲染。

### 嘉兴那片为什么是空的（实证）

用 Overpass 拉 OSM 原始数据（bbox `30.8295~30.8350N / 120.7355~120.7425E`）：

- **只有 15 个要素**，全部出自 2 位志愿者：`EnumMapper`（2022-05-24）、`rza31`（13 个）
- **最后编辑：2024-10-05**，之后**再没人动过**
- 内容：1 条 `highway=primary`（就是东方北路）、几条小路/桥、水系、**5 栋 `building=yes` 无名建筑**

⇒ 既没有 `amenity=university` 的校园面，也没有「北京理工大学嘉兴校园」这个名字。
**瓦片上看不到校园 = 社区数据缺口，不是数据旧**（校园 2025 才交付，2024-10 之后没人补）。
对比：中关村 / 良乡 / 珠海在 OSM 上画得比较全，所以那三颗按钮点过去能看到校园。

### ✅ 已修：OSM 署名（v1.9.16）

OSM 数据是 **ODbL** 授权，**要求署名**（`© OpenStreetMap contributors`），
而此前全仓库（`features/map` 及所有 `.kt/.md/.xml`）**没有任何地方提到 OpenStreetMap**，
地图页也没有署名 —— 这是**许可合规缺口，不是可选项**。

**已于 v1.9.16 补上**：`MapScreen` 右下角一行小字（半透明底 + 可点击跳
`https://www.openstreetmap.org/copyright`）。位置是挑过的 —— 左上角是 FAB 列、
底部中间是设置栏，只剩右下是空的；设置栏弹出期间会临时盖住它，关掉即露出。

### 顺带：想让嘉兴校园出现在底图上

任何人都能编辑 OSM。给院区加一个 `amenity=university` + `name=北京理工大学嘉兴校园`
（或先加一个点），提交后瓦片通常**几小时到几天**更新。
⚠️ 但这需要 OSM 账号、**得用户自己提交**（不代为提交）。

## 十五、功能盘点 + 新功能思路（2026-09-27）

### 15.1 现状盘点：哪些接口我们做了、哪些上游留白了

把 `api` 模块暴露的 12 个 Service 逐个对照 `data`/`features` 的调用情况：

| 接口 | 内容 | 状态 |
|---|---|---|
| `posters` + `reaction` + `message` + `manage` | 话廊 / 点赞评论 / 消息 / 举报 | ✅ 上游做了，我们在用 |
| `user` / `upload` / `app` / `version` | 账号 / 图片上传 / 应用 / 版本 | ✅ 在用 |
| `eclass` / `schoolLexue` | 延河课堂 / 乐学 | ✅ 我们在用 |
| `schoolJxzxehall` | 课表 / **考试** / 学期 / 首日 / 校区楼 | ✅ 在用（`DefaultCoursesRepo`）|
| `schoolClassroom` | 空教室 | ✅ 在用 |
| `scoreQuery` | 成绩（异步 challenge） | ✅ 我们在用 |
| **`papers`** | **文章 / 经验贴** | ❌ **接口齐全，业务零调用** |
| **`courses`** | **课程库 / 课程资料** | ❌ **接口齐全，业务零调用** |
| **`variables`** | 按 `obj` 取字典 | ❌ 零调用（辅助性） |

⇒ **上游的「内容社区」只做了一半**：`posters`（话廊）做了，`papers`（文章）与 `courses`（课程库）
**留白**。**这是最值得挖的方向 —— 接口、鉴权、分页、排序、上传通道全都现成。**

### 15.2 新功能思路（按性价比排序）

#### A 类：接口已备好，只差 UI（增量价值最高）

**A1 文章 / 经验贴（`/papers`）**
- `getPapers(search, order, page)`；`PapersOrder = RAND / NEW / LIKE`
  —— **`RAND` 说明产品本意是「随机刷一篇读」**
- 详情含：标题、简介、正文、作者（**可匿名**）、点赞数、评论数、**`publicEdit` 公开编辑**（wiki 式共建）
- 增删改齐全：`postPaper` / `putPaper` / `deletePaper`
- **落地形态**：「网」页里加「文章」入口 → 列表（随机 / 最新 / 高赞）→ 详情（点赞、评论、原作者可编辑）
- **场景**：新生攻略、选课经验、保研考研帖、校园生活指南

**A2 课程库 + 资料库（`/courses`）**
- `getCourses(search, order, page)`，`CoursesOrder = LIKE / COMMENT / RATE / NEW` → **课程评价/评分**
- `getCourseById(id)` 详情
- **`getCourseUploadUrl(name, number, type)` + `postCourseUploadLog`** → **一条完整的「上传课程资料」通道**
  - `MaterialType = PPT / BOOK / **EXAM** / OTHER` → **能传往年试卷**
- `getCourseHistories(number)` → 同一课程编号的历届记录
- **落地形态**：搜课程 → 看评价 → 下课件 / 往年题
- ⚠️ 上传会**把内容发到公共服务器**，默认先只做「看」，上传要单独确认

**A3 `variables`（按 `obj` 取字典）** —— 辅助性，等 A1/A2 需要时再包。

#### B 类：现有数据的自然延伸（工作量小）

| # | 想法 | 现在缺什么 |
|---|---|---|
| **B1** ✅ | **考试日程卡片 + 开考提醒** | ✅ **v1.9.14 已完成** —— 列表入口 + 考前一天/考前双窗口提醒，见第十七节 |
| **B2** | **校园网流量趋势**（原 H1） | 接口 `[6]` 是累计计数器，每天记一次就能算出「每天用了多少」；可直接复用 `CampusCardBalanceStore` 的采样范式 |
| **B3** | **成绩原生页 + 每学期 GPA 走势**（原 H3） | 数据已拿得到（`ScoreQueryApiService`），现在只是通知直链到 WebView |
| **B4** | **「现在去哪儿自习」** | 空教室 + 当前时间都有了，缺一个「当下最优」入口（如首页一张卡：离你最近的空教室） |
| **B5** | 地图：记住上次看的校区 / 把当前校区名写出来（原 H5 / H8） | — |
| **B6** | 一卡通余额趋势上「我」页卡片（原 H2） | — |

#### C 类：工程 / 合规

- **C1 OSM 署名**（见第十四节，ODbL 要求）
- **C2 提醒去重标记改同步写**（原 H4）

### 15.3 建议顺序

1. **A1 文章板块** —— 新增一个完整功能模块，接口现成、风险低，内容型功能对「天天打开」很有帮助
2. **B1 考试卡片 + 提醒** —— 数据都躺着了，接一下即可，体感提升明显
3. **B2 + B3** —— 把校园服务与成绩做透
4. **A2 课程库**（先只读；上传单独确认）

### 15.4 ⚠️ 方法论教训（本轮踩到）

判断「某个接口有没有被用」时，**不能用属性名 grep**（如 `api.papers`）——实际调用可能走别的
注入路径。本轮就因此**误判过两次**：`schoolJxzxehall`（显示 0 次，其实在用）、
`scoreQuery`（显示 0 次，其实在用）。**可靠判据是「方法名 + 类型名」**：
搜 `getPapers` / `getCourseById` / `PapersApiService` 这类专有符号。

### 19.1 筛选判据（先把尺子说清楚）

一条想法要留下，必须至少满足两条：

1. **拿得到数据**（有接口 / 有可抓的公开页），且不需要我们做支付或碰隐私数据
2. **官方入口没覆盖**，或**覆盖得很差**（网页版弱、没有提醒、没有本地能力）
3. 能落到我们的**既有强项**上：桌面组件 / 提醒 / 本地数据 / 原生体验

⇒ 于是「AI 问答」「校园支付」「请销假」这类**看起来热闹但不符合**的，直接出局。

### 19.3 新功能：四个主题

#### 主题 A：通勤（**全新空白，痛点真实**）

**A1 摆渡车「下一班」** ✅ **v1.9.17 已完成**（课表页「交通」页签；班车按调研**不做**，理由见 `docs/campus-bus.md`）

- 背景：良乡 ↔ 中关村 **36 km**，走读/跨校区上课的人**每天都要赌发车**。
- ⚠️ **完整调研见 `docs/campus-bus.md`**（2026-09-27），三条关键修正：
  1. **没有「校车」这个说法** —— 只有摆渡车与班车（第三方攻略原话）
  2. **摆渡车不是"每 20 分钟"**：官方图（2021/2022 上传）说 20 分钟，而第三方
     **2026-05-05 制表**说密集时段 **16 分钟**一班、且**节假日有加发** ⇒ **官方图已过期**
  3. ⚠️ **班车要购票预约**（i北理，**学生只能提前 1 小时**；彩虹班车走公众号可提前多日）
     ⇒ **发车提醒对班车没有意义**
- ⇒ **收缩后的范围**：
  - ✅ **摆渡车**：选站点（地铁站 / 北校区徐特立图书馆）→「下一班 HH:mm · 还有 N 分钟」
    + 发车提醒 + 节假日加发可切换 + **必须标注来源与日期**
  - ✅ **班车**：只做**乘车点 + 购票指引**（"要在 i北理 买票、学生只能提前 1 小时"
    这件事本身很多人不知道，是真正有价值的信息）
  - ❌ 不做班车发车提醒；❌ **不把第三方与官方的时间混用**（buspedia 说班车末班 22:50，
    官方图写 21:10，**无法核实**）
- 完整时刻表（两站点 + 节假日加发）已抄进 `docs/campus-bus.md` 第 1 节

#### 主题 B：把「自习」做成闭环（我们已经做了 3/4）

现状：**空教室** ✓（三级折叠）、**图书馆座位** ✓（就是座位预约，见 `school-portal-map.md` 第三节）。

**B2 ✅ 违约提醒（座位 + 研讨室）**

- 契约：违约累计 **5 次暂停预约 7 日** —— 这是**真实损失**，而官方 App 没有任何提示。
- ✅ **v1.9.19 起做，v1.9.23 换成权威数据源**：
  **`POST /api/Member/reneges {"type":1|2}`**（1 = 座位、2 = 研讨室）——
  就是 h5「我的中心 → 我的违约」(`#/my/contract`) 用的接口。
  字段 `nameMerge/name/time/status/statusname`，无 id、无分页。
- ⚠️⚠️ **v1.9.19 曾判断「服务端没有违约次数接口」，那是错的**。错因值得反复引用：
  **未登录时它与其他 seatlib 接口完全一样，是 `HTTP 200 + code 10001`**，
  用无 token 的盲探很容易把「要登录」误读成「没有这个功能」。
  ⇒ **判断「服务端有没有某功能」，先去 h5 分包里找函数名**（静态资源不用登录）。
- 本地**不再有任何推算**：v1.9.19 那套 `Watch`/`detect`/手动补记/撤销/清空**已整块删除**
  （数字以服务端为准，本地改它只会制造第二个真相）。
- 本地只剩「**见过的 key**」（`seat_renege_keys_<type>`）用于判断**新增**并发通知；
  ⚠️ 必须有「**首次只建基线、不通知**」这一步，否则一装 App 就会把历史违约当新增报一遍
  （v1.9.25 修）。
- 界面：违约卡（`违约 N/5` + 明细弹窗，「明细」按座位/研讨室分节）+ 有新增时的通知。

#### 主题 E：AI 问答 —— **只在「问我的数据」这个子集上做**

⚠️ 这是**修正后的判断**：最初我把「AI 问答」整块判成不做，理由是"成本高、与核心价值无关"——
**两条都站不住**（详见 `docs/school-portal-map.md` 第六节）：
平台已有**免密钥模型调用**；而 AI 恰恰是**本地私有数据的放大器**，不是无关项。

但必须切开：

| 类型 | 判断 |
|---|---|
| 「怎么办学生证」这类**问学校事务** | ❌ 不做 —— 学校有官方资料库、i北理 A+Campus 已覆盖，我们做只会更旧 |
| 「我明天几节课」「我还有多少流量」「该去哪自习」这类**问我的数据** | ✅ 做 —— **数据只在本机，网页与钉钉答不了** |

**两条硬约束（不满足就不做）**：

- **A：AI 只做「理解问题 → 选工具 → 组织措辞」，不负责计算与检索。**
  数字必须来自确定性代码（否则「明天 08:00 高数」这类幻觉会**直接误事**）。
  本质是**给已有能力加一层自然语言入口**。
- **B：隐私开关默认关 + 明确告知 + 脱敏**（不发学号/姓名/教师名）。
  用户此前明确要求「出分通知不含分数」，说明对成绩敏感。

**时机**：它是**上层薄壳**，要等下层把事算清楚 —— 班车（A1）、自习聚合（B1）、
GPA（C2）就位之后再做，否则会做出一个"什么都能问、答案经常错"的壳子。
